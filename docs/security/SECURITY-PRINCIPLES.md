# Security Principles

## 1. Least Privilege

Graph- und Entra-Berechtigungen werden so granular wie möglich vergeben.

## 2. No standing privilege

Privilegierte Rollen sollen, soweit technisch möglich, zeitlich begrenzt und über PIM aktiviert werden.

## 3. Strong Authentication

Privilegierte Konten benötigen phishing-resistente Authentifizierung, sofern der jeweilige Use Case dies unterstützt.

## 4. Emergency Access

Notfallkonten werden separat behandelt, überwacht und regelmäßig getestet.

## 5. Safe Rollout

Sicherheitsrichtlinien werden nicht ungeprüft tenantweit erzwungen.

## 6. Auditability

Relevante Änderungen müssen nachvollziehbar sein.

## 7. Secrets

Keine Secrets im Repository.

## 8. Synthetic Data

Nur fiktive Testdaten dürfen veröffentlicht werden.
